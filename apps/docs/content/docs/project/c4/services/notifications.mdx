# Notifications Module - Архітектурна Документація
## Огляд проекту
### Архітектура: 
Багатошаровий .NET додаток з використанням патерну Repository та Service Layer

### Технології:
.NET Core / ASP.NET Core
Entity Framework Core
AutoMapper
SignalR (для real-time оповіщень)
Dependency Injection

### Основні компоненти:

DTO Layer (s_smarttender.DTO) - моделі передачі даних
Infrastructure Layer (s_smarttender.infrastructure) - база даних та моделі
Service Layer (s_smarttender.services) - бізнес-логіка
Gateway - API endpoints та контролери

### Модуль Notifications відповідає за:

Збереження та відображення системних оповіщень
Інтеграцію з внутрішнім чатом (InnerChat)
Підписки користувачів на події
Відстеження статусів переглянутих повідомлень

## Рекомендації

### Виявлені патерни проектування

* Repository Pattern - доступ до даних через LoggerDbContext 
* Service Layer Pattern - бізнес-логіка інкапсульована в NotificationService 
* DTO Pattern - чітке розділення між моделями БД та моделями передачі даних 
* Dependency Injection - використання DI для всіх залежностей 
* Feature Toggle Pattern - використання Growthbook для переключення між старою/новою реалізацією InnerChat 
* Composite Pattern - комбінування результатів Notifications та InnerChat в Events 

### Потенційні проблеми

* N+1 Query Problem - потенційно в методах з Include можуть виникати зайві запити
* Hard-coded PAGE_SIZE - константа PAGE_SIZE = 10 може бути винесена в конфігурацію
* TODO коментар - логіка TagMe не реалізована (GetNotifications метод)
* Dual API calls - паралельні виклики до Notifications + InnerChat можуть уповільнювати відповідь
* JSON serialization в БД - поле Properties зберігається як JSON string, що ускладнює пошук
* Відсутність пагінації - в методі GetNotifications немає явної пагінації
* Exception handling - немає явної обробки помилок HTTP запитів до CommercialApi

### Пропозиції щодо оптимізації

* Кешування - додати кеш для частих запитів (GetLastEvents, GetLastNotifications)
* Пагінація - реалізувати Skip/Take для великих списків оповіщень
* Async improvements - використати IAsyncEnumerable для стрімінгу великих результатів
* Bulk operations - оптимізувати масове оновлення Viewed статусів
* Circuit Breaker - додати обробку збоїв для HTTP запитів до CommercialApi
* Event Sourcing - розглянути можливість використання Event Sourcing для історії подій
* SignalR integration - більш тісна інтеграція з SignalR для real-time оновлень
* Database indexes - переконатися в наявності індексів на:
* Notification.SubscriptionId + Viewed
* NotificationMessage.Timestamp
* EventSubscription.UserLogin + Unsubscribed
* Refactoring - винести спільну логіку для Events у окремий EventAggregatorService
* Monitoring - додати логування та метрики для відстеження продуктивності

### Архітектурні покращення

* CQRS Pattern - розділити команди (Save, Update) та запити (Get) в окремі сервіси
* Mediator Pattern - використати MediatR для обробки команд/запитів
* Specification Pattern - винести фільтри в окремі Specification класи
* Unit of Work - обгорнути транзакції в UnitOfWork патерн
* Domain Events - використати domain events замість прямих викликів UpdateUserStatistic
