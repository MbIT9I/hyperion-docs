# InnerChat Module - Архітектурна Документація

## Огляд проекту

### Технології та патерни:
- **Архітектура**: Clean Architecture (Abstractions → Application → Infrastructure)
- **Патерни**: CQRS з використанням MediatR для обробки команд/запитів
- **ORM**: Entity Framework Core (DbModels з навігаційними властивостями)
- **Message Broker**: Асинхронна комунікація через RabbitMQ/MassTransit
- **Mapper**: AutoMapper для перетворення між шарами
- **Dependency Injection**: Scoped lifetime для сервісів

### Компоненти:
- **InnerChat.Abstractions** - моделі даних, DTO, enums, запити
- **InnerChat.Application** - бізнес-логіка, use cases, сервіси
- **InnerChat.Infrastructure** - API контролери, репозиторії

### Потенційні проблеми

**Performance Issues**

⚠️ N+1 Query Problem: Завантаження ParentMessages відбувається окремим запитом після основного. Рекомендація: використати .Include(x => x.ParentMessage) в основному запиті \
⚠️ Великі Attachments: Content зберігається як byte[] в БД. Для великих файлів краще використовувати Blob Storage (Azure Blob, S3) \
⚠️ Properties як JSON string: В EventSubscriptionEntityDb.Properties зберігається JSON. Краще використати JSON column type або окрему таблицю

**Concurrency**

❌ Відсутня перевірка optimistic concurrency для одночасного редагування \
Рекомендація: додати RowVersion або Timestamp для критичних таблиць

**Security**

✅ Authorization через [Authorize] атрибут \
⚠️ Відсутня перевірка прав доступу до вкладень при завантаженні \
Рекомендація: перевіряти чи користувач має доступ до entity перед видачею файлу

**Data Consistency**

⚠️ Attachments створюються з MessageId = null, потім оновлюються. Можливі orphaned attachments \
Рекомендація: Background job для очищення старих непрв'язаних attachments

**Error Handling**

⚠️ В CreateMessages при відсутності підписки повертається null замість ExecutionResult з помилкою \
Рекомендація: використовувати ExecutionResult.Fail() для консистентності

Кешувати EventSubscriptionEntity (рідко змінюються)

Query Optimization
```csharp
// Замість:
var messages = await GetMessagesAsync();
var parentIds = messages.Select(x => x.ParentMessageId);
var parents = await GetMessagesByIds(parentIds);

// Використати:
var messages = await context.ChatMessages
    .Include(x => x.ParentMessage)
    .Include(x => x.Tags)
    .Include(x => x.Attachments)
    .AsSplitQuery() // Для великих include

```

### Особливості реалізації

* Self-referencing Messages: ParentMessageId дозволяє створювати threads (відповіді на повідомлення)
* Dual View Tracking: Viewed (прочитано в чаті) vs EventViewed (побачено в нотифікаціях)
* Pre-upload Attachments: Файли завантажуються окремо перед створенням повідомлення
* JSON Properties: EventSubscriptionEntityDb.Properties зберігає додаткові metadata в JSON форматі
* Tag Value як JSON: Для User tags зберігається ```{login: "username"}``` в JSON форматі
